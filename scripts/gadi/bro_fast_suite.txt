# Single-algorithm suite for "BRO (Fast)" - the paper's own lower-replay-ratio variant, not a
# separate implementation. standalone/bro.py already supports it directly via
# --updates-per-step 2 (vs. the default 10) - same BroNet critic, dual-actor optimism, reset
# schedule, everything else unchanged. Exists because the full replay-ratio-10 BRO measured
# ~6-8 steps/sec on Gadi's GPU (bro_probe_suite.txt) - too slow to finish 1M steps even in the
# raised 24h walltime (~40-46h needed at that rate). Replay ratio 2 does 5x fewer critic
# gradient steps per env step, which should close most of that gap.
#
# PBS Pro rejects a single-task array (-J 0-0 is "illegal"), so this file has one real line
# and needs -J 0-1 - index 1 fails cleanly in <1s ("no suite line for index 1"), no GPU cost.
#
# Submit (recommended: probe a short budget first to get a real sps number for THIS variant,
# same as the full-replay-ratio probe did, before committing to the full 1M steps):
#   GYM_ENV=Ant-v5 SEED=0 TOTAL_STEPS=50000 SUITE=scripts/gadi/bro_fast_suite.txt \
#       qsub -v GYM_ENV,SEED,TOTAL_STEPS,SUITE -J 0-1 scripts/gadi/train_standalone_suite.pbs
# Then, once you have a throughput number and know it'll fit the walltime, the real run(s):
#   GYM_ENV=Ant-v5 SEED=0  TOTAL_STEPS=1000000 SUITE=scripts/gadi/bro_fast_suite.txt \
#       qsub -v GYM_ENV,SEED,TOTAL_STEPS,SUITE -J 0-1 scripts/gadi/train_standalone_suite.pbs
#   (repeat with SEED=1, SEED=42 for the same 3-seed comparison as the other algorithms)
standalone/bro.py --updates-per-step 2
